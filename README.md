# Этап 3. VFS (виртуальная файловая система)

## Описание

На этом этапе реализована загрузка виртуальной файловой системы из
XML-файла в память. Все операции с VFS выполняются только над деревом
структур в оперативной памяти — исходный XML-файл не изменяется и не
распаковывается на диск.

Бинарное содержимое файлов (поле `content` в XML) кодируется в base64
прямо внутри XML-документа, поскольку XML — текстовый формат и не
может напрямую содержать произвольные байты.

## Функциональность

- Парсинг XML-файла VFS в дерево структур `Directory`/`File` в памяти
  (`encoding/xml` + ручное декодирование `content` из base64)
- Обработка ошибок загрузки VFS:
  - файл по пути `--vfs` не найден
  - файл найден, но содержит невалидный XML
  - содержимое файла — невалидный base64
- Заголовок окна после загрузки отображает реальное имя VFS
  (взамен заглушки, использовавшейся на этапах 1–2)
- Поддержка произвольной вложенности директорий

## Формат VFS-файла

```xml
<vfs name="myvfs">
  <directory name="root">
    <file name="readme.txt" content="SGVsbG8sIFZGUyE=" />
    <directory name="home">
      <directory name="user">
        <file name="notes.txt" content="dGVzdCBjb250ZW50" />
      </directory>
    </directory>
  </directory>
</vfs>
```

## Структура проекта

```
src/
├── main.go
└── internal/
    ├── command/
    ├── config/
    ├── executor/
    ├── parser/
    └── vfs/                    — парсинг XML, дерево Directory/File
tests/
└── stage3/
    ├── vfs_minimal.xml         — один файл, без вложенности
    ├── vfs_multiple.xml        — несколько файлов в одной папке
    ├── vfs_nested.xml          — вложенность >= 3 уровня
    ├── vfs_invalid.xml         — намеренно битый XML
    ├── script_minimal.txt      — сценарий для минимальной VFS
    ├── script_nested.txt       — сценарий обхода вложенной VFS
    ├── script_errors.txt       — сценарий с ошибками навигации
    └── run_stage3.sh           — прогон всех случаев
```

## Запуск

```bash
cd src
go build -o vfs-shell .

./vfs-shell --vfs=../tests/stage3/vfs_nested.xml --script=../tests/stage3/script_nested.txt
```

Либо все случаи сразу:

```bash
sh tests/stage3/run_stage3.sh
```

## Проверка

| # | Сценарий                                          | Ожидаемый результат                                          |
|---|------------------------------------------------------|-----------------------------------------------------------------|
| 1 | `--vfs=vfs_minimal.xml`                              | VFS загружается, заголовок окна показывает имя `minimal`        |
| 2 | `--vfs=vfs_multiple.xml`                             | Все файлы корневой директории загружены корректно                |
| 3 | `--vfs=vfs_nested.xml` + `script_nested.txt`         | `cd`/`ls` корректно проходят вложенность в 3+ уровня            |
| 4 | `--vfs=vfs_nested.xml` + `script_errors.txt`         | `cd` в несуществующую папку — ошибка, приложение не падает       |
| 5 | `--vfs=vfs_invalid.xml`                              | Ошибка парсинга XML выводится в интерфейс, окно не закрывается   |
| 6 | `--vfs=nonexistent.xml`                              | Ошибка открытия файла, окно остаётся открытым                   |

## Известные ограничения этапа

`ls` и `cd` уже умеют реально ходить по загруженному дереву VFS, но
остальные команды (`rev`, `clear`, `rm`, `chown`) появятся на этапах
4 и 5.
