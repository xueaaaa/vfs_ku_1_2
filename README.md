# Этап 4. Основные команды

## Описание

На этом этапе команды `ls` и `cd`, которые ранее были заглушками
(этап 1) и работали только с аргументами, теперь полноценно работают
с деревом VFS, загруженным на этапе 3. Дополнительно реализованы
команды `rev` и `clear`.

## Функциональность

- `ls` — выводит список файлов и вложенных директорий **текущей**
  директории VFS (а не просто переданные аргументы)
- `cd` — перемещает текущую директорию по дереву VFS:
  - поддержка перехода на уровень вверх (`..`)
  - поддержка перехода в корень (`/`)
  - поддержка составных путей (`a/b/c`)
  - ошибка при переходе в несуществующую директорию, без падения
    приложения
- `rev` — читает файл из текущей директории VFS по имени и выводит
  его содержимое, перевёрнутое посимвольно
- `clear` — очищает область вывода в интерфейсе
- Все ошибки выводятся как сообщение, не прерывая работу
  приложения и не мешая выполнению остальных команд скрипта

## Запуск

```bash
cd src
go build -o vfs-shell .

./vfs-shell --vfs=../tests/stage3/vfs_nested.xml --script=../tests/stage4/script_full.txt
```

Либо готовым скриптом:

```bash
sh tests/stage4/run_stage4.sh
```

## Проверка

| # | Команда в сценарии              | Ожидаемый результат                                      |
|---|-----------------------------------|-------------------------------------------------------------|
| 1 | `ls` в корне                      | Список файлов и папок корня VFS                             |
| 2 | `cd home` → `ls`                  | Список содержимого `home`, а не аргументы команды            |
| 3 | `cd user` → `cd documents` → `ls` | Корректный обход вложенности 3+ уровня                       |
| 4 | `rev notes.txt`                   | Содержимое файла выводится перевёрнутым                      |
| 5 | `rev missing.txt`                 | Ошибка "файл не найден", приложение не падает                |
| 6 | `cd ..` × 3                       | Корректный подъём до корня                                   |
| 7 | `clear`                           | Область вывода полностью очищается                           |
| 8 | Команды после `clear`             | Продолжают работать как обычно                               |

## Известные ограничения этапа

`rev` только читает и выводит перевёрнутое содержимое — файл в VFS не
изменяется. Команды, реально меняющие состояние VFS (`rm`, `chown`),
появятся на этапе 5.
